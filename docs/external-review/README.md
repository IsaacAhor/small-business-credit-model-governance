# External review packets

Review selected methods and records for model-risk governance, adverse-action
reason traceability, and ongoing oversight of small-business credit models.
The project is a synthetic demonstration. We welcome critical, mixed, or
inconclusive assessments of the work actually examined.

## Choose your packet

If you received a specific packet, start there. Each packet contains its
assignment, source identity, essential instructions or prepared materials,
known limitations, and what to return.

### Technical Implementation Reviewers

[Open the technical review packet](technical-review.md). Reproduce outputs,
inspect implementation, and design independent challenges. Requires Python
and the fixed source. Return execution evidence, challenge results, findings,
and your conclusion.

### Credit Governance and Adverse-Action Reviewers

[Open the credit governance and adverse-action packet](practitioner-assessment.md).
Trace prepared records, assess a governance gap, and specify the next action.
No installation required. Return a short task response and assessment of
practical fit.

### Methodology and Evaluation Reviewers

[Open the methodology and evaluation packet](methodology-assessment.md).
Assess claims, assumptions, reference answers, and evaluation design. No
execution required for the methods-only assignment. Return a short critique
and proposed evaluation improvements.

Use [the group definitions](reviewer-groups.md) to assess fit by experience.
One person may cover multiple functions; record each scope separately. That
does not create multiple independent reviews or organizational endorsement.
Agree an effort cap before starting; partial work is a valid recorded outcome.

## Agree a fixed assignment

These packets describe **v0.12.0**, source commit
`3baafca5b695c6f80d5c84a2c8b4fa184d6f59ca`. The instructions were added later
and are absent from that software release archive.

Before inviting a new reviewer, the maintainer uses [target selection](current.md)
to confirm the intended software and matching packet. Send the selected packet
directly, using its commit-pinned URL, and agree scope, effort, and return method.
Record the packet revision separately from the software commit. A reviewer with
an agreed assignment keeps those versions; a newer release does not replace it.

The [shared protocol](protocol.md) contains the full agreement, findings,
response, retest, and sharing rules summarized in the packets. The
[fixed target sheet](targets/v0.12.0.md) preserves source references and known
issues. These are supporting references, not a second starting sequence.

These documents do not establish a completed review, correct real-world
notices, model-explanation faithfulness, adoption, or legal compliance.
