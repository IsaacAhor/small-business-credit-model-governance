# Select a review target

For a new assignment, open the
[latest published release](https://github.com/IsaacAhor/small-business-credit-model-governance/releases/latest).
Open the **Review target** link in that release's notes. It points to the
matching sheet in the tagged source. Use the sheet with the technical or
practitioner brief, and record the exact source commit and instruction revisions
when agreeing the assignment. The latest-release link follows new releases;
an agreed review stays fixed.

For each future release, the maintainer prepares its target sheet and adds the
version-pinned link to the release notes. A small release check requires the
matching sheet, version heading, and link. Commands, results, and limitations
still require maintainer verification. This check is not an external assessment.

## Earlier release

The existing **v0.12.0** release predates this routing convention. If the latest
release is v0.12.0, use its [preserved target sheet](targets/v0.12.0.md) with
the [technical brief](technical-review.md) or
[practitioner brief](practitioner-assessment.md). Its disclosed limitations
remain part of the assignment. The release and its archive are unchanged.

If another release lacks a Review target link, resolve the missing
instructions before starting. Do not silently substitute another version's
sheet or assume that a newer release has corrected earlier findings.

## Reviews already agreed

Continue using the exact agreed source and instruction revisions. A new release
does not move an existing review. A switch or retest requires a separate
agreement under the [target-change procedure](protocol.md#changing-the-review-target).
Preserve original results, unresolved findings, and historical links.
