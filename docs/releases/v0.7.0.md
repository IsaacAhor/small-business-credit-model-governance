# v0.7.0

Phase 5 model-change and validation-review workflow.

## What This Release Adds

- A change-validation module (`src/credit_gov/validation.py`) that compares a
  prior snapshot of the governed records against the current dataset records for
  the same model:
  - a model-version diff (effective date, change summary, assumptions,
    limitations, linked validation record)
  - a threshold-set diff keyed by metric, reading a value change as tightened or
    loosened where the comparison rule is unchanged, and flagging added, removed,
    and rule-changed thresholds
  - a reason-code mapping diff keyed by reason code, separating a structural
    text or driver change from a mapping-version bump
- A change-impact summary with a configurable materiality reading and derived
  review actions (for example, confirming that a removed threshold is an approved
  decision, and checking that added reason codes still produce specific, accurate
  adverse-action reasons).
- A reviewer signoff record tied to the specific current version and the
  evidence-pack run, with the actions required before promoting the version to
  active.
- Optional integration into the monthly monitoring workflow, triggered by the
  presence of `prior-model-version-record.json`. When present, the run emits
  `model_change_validation_results.json` and `model_change_validation_report.md`,
  adds a report section, and strengthens `reviewer_signoff.md`. Prior threshold
  and reason-code snapshots are each optional within the review.
- A standalone CLI, `scripts/run_change_validation.py`, for focused change review.
- Prior-version comparison inputs for the portfolio dataset and a regenerated
  `examples/evidence-packs/monthly-portfolio/` pack that now includes the
  change-validation artifacts.
- Ten Phase 5 tests covering the model-version, threshold-set, and reason-code
  diffs, the summary and report output, the monitoring integration when Phase 5
  inputs exist, and the no-op behavior when they are absent.

## What This Release Demonstrates

A repeatable change-governance step: given two versions of a model's governed
records, the workflow produces a deterministic, reviewer-readable impact summary
and a signoff record that names the version, the evidence pack, and the actions a
validator would need to close before promotion.

## Limitations

- Synthetic data only. No production model change is represented.
- Change materiality is a configurable governance heuristic, not a legal or
  regulatory determination.
- Signoff fields are illustrative placeholders; no independent validation has
  occurred.
- Regulatory references in the derived review actions (Regulation B 12 CFR
  1002.9 reason specificity; SR 26-2 principles-based model-risk oversight and
  change management) are design anchors, not evidence of compliance.

## Scope Notes

Synthetic demonstration milestone. Not production deployment, institutional
adoption, external recognition, or regulatory acceptance.
