# Release v0.12.0 - Reason Traceability and Recourse Assessment

Release date: 2026-09-03

Git tag: [v0.12.0](https://github.com/IsaacAhor/small-business-credit-model-governance/tree/v0.12.0)

## What This Release Adds

- Clarifies current reader-facing terminology: legacy programmatic `fidelity`
  identifiers mean record-level source-to-notice traceability and
  reconciliation, not unique explanation truth, causality, actionability,
  recourse, or legal sufficiency.
- Adds a separate optional recourse-assessment sidecar with six mirrored JSON
  Schema 2020-12 contracts, typed models, all-or-none bundle validation,
  deterministic finite enumeration, conservative statuses, and explicit
  uncertainty.
- Adds synthetic valid and invalid fixtures, a deterministic eleven-file
  reviewer pack, protected-core hash checks, standalone and installed commands,
  documentation, and regression coverage.
- Restricts the first recourse provider to one baseline-specific subject per
  bundle, links feature-schema versions, constrains the executable withholding
  rule, and rejects internally or bundle-relationally inconsistent output
  records.
- Adds a controlled GitHub release workflow with exact-tag binding, package and
  repository checks, fail-closed artifact inspection, checksums, a protected
  publication environment, and post-publication asset verification.

## What This Release Demonstrates

The release demonstrates a reproducible, reviewer-facing separation between
source-to-notice traceability controls and optional recourse assessment. It
also demonstrates strict contract validation, deterministic enumeration, and
portable evidence-pack construction on synthetic inputs.

## What This Release Does Not Demonstrate

This release does not establish real-world action-set feasibility, production
model access, applicant usefulness, institution adoption, independent
validation, legal compliance, increased approvals, improved credit access, or
regulatory approval. A review of another version or module does not validate
this release.

## Compatibility

The release does not rename or repurpose the existing reason-fidelity module,
types, keys, policies, tests, schemas, commands, historical notes, or curated
reason packs. Recourse is absent from the core mandatory schema tuple and
monthly monitoring result, so existing datasets remain valid without a
recourse bundle.

## Verification

The tagged tree is checked through the repository validators, the Python 3.10
through 3.13 test matrix, source and installed-package tests, distribution
inspection, SHA-256 verification, and the controlled release workflow.
